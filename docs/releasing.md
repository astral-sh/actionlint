# Releasing the Astral fork

Astral releases are published only by `.github/workflows/release.yml`. They are built from the exact
commit selected by a manual workflow dispatch on `main`. The workflow does not bump versions, update
`main`, publish containers, or update upstream package-manager repositories.

## Build and publish

Dispatch `Release` with `tag=dry-run` first. This builds all eleven supported upstream targets with
Go 1.26.6 and no CGO. Builds have no publication or OIDC permissions and do not consume shared Actions
caches. The workflow checks out the exact source SHA and requires a clean tree. Pinned GoReleaser
builds and packages the binaries once without publishing. Before signing, a small payload check
requires the expected archives and SBOMs and verifies GoReleaser's SHA-256 checksums. Protected jobs
use those same preserved artifacts; they do not rebuild them.

Each target has an archive and a CycloneDX 1.6 SBOM generated by pinned Syft. The release also contains GoReleaser's SHA-256
checksums and a Sigstore provenance bundle. Archives contain the binary and committed documentation,
including the man-page source; they do not run a separate documentation generator. These SBOMs inventory
the archives, not a container's operating-system packages or the complete build environment.

Choose an unused `v1.x.y` tag, optionally with a SemVer prerelease suffix, and dispatch `Release` on
the reviewed `main` revision. Inspect the exact source SHA and built artifacts before approving
`release-gate`. The signing job verifies the complete artifact set and creates keyless GitHub/Sigstore
build-provenance attestations. Its successful `release` deployment permits tag creation. The publisher
verifies every artifact against that signed bundle before using the repository token to publish.

The publisher creates the tag at the dispatch's exact SHA, uploads a draft release, checks the uploaded
asset digests, and publishes it. GitHub then makes the release immutable and supplies its own release
attestation. There is no long-lived signing key and no separate API gate that polls source CI, CodeQL,
or Zizmor; the normal source-review requirements, release builds, and protected environments govern
publication.

If publication fails after creating a tag or draft, stop and inspect the existing tag, source SHA, and
uploaded assets. Do not delete or move the tag, overwrite a published release, or disable protections.
Recovery of an incomplete draft requires a separately reviewed operation; the workflow does not silently
reuse a tag or replace existing assets.

GitHub can reject release creation with `GITHUB_TOKEN` if workflow files at the selected commit differ
from the current default branch. If `main` changes during approval and this restriction applies, inspect
any partial publication and dispatch a newly reviewed revision; do not add a broader token to bypass it.

## Verify a release

Obtain the full source commit and expected archive digest from the reviewed adoption record. Replace
the placeholders below with those immutable values; do not select a floating latest release.

```sh
tag=v1.X.Y
commit=FULL_REVIEWED_COMMIT_SHA
archive=actionlint_1.X.Y_linux_amd64.tar.gz
digest=EXPECTED_ARCHIVE_SHA256

gh release download "$tag" --repo astral-sh/actionlint \
  --pattern "$archive" --pattern 'actionlint_*_attestation.json'
printf '%s  %s\n' "$digest" "$archive" | sha256sum --check -
gh release verify "$tag" --repo astral-sh/actionlint
gh attestation verify "$archive" --repo astral-sh/actionlint \
  --bundle actionlint_1.X.Y_attestation.json \
  --signer-workflow astral-sh/actionlint/.github/workflows/release.yml \
  --source-ref refs/heads/main --source-digest "$commit" \
  --signer-digest "$commit" --deny-self-hosted-runners
```

Only unpack or execute the archive after verification succeeds. The source ref is `main`, not the
release tag: the tag is created after the build and approval. The commit, signer-workflow digest, and
immutable-release attestation bind the release to the reviewed source despite that ordering. A valid
signature establishes the publishing identity and artifact integrity; it does not replace source review
or semantic regression testing.
